# 用 AI + Markdown 搭建研究笔记系统

你读到一篇好文章。你收藏了。然后……再也没打开过。

问题不是你收集得不够——而是散落的笔记没有地方住，也彼此没有联系。研究笔记系统的意义正在于此。而 Markdown 是这个系统能跑起来的那个格式。

下面是四层结构，今天就能搭好，无聊的部分全部交给 AI。

## 四层结构：收集 → 整理 → 连接 → 检索

- **收集** —— 任何内容快速变成 Markdown
- **整理** —— 每篇笔记用同一个骨架
- **连接** —— 笔记彼此关联，想法才会复利
- **检索** —— 几秒钟找到你要的东西

## 第 1 层：收集——把一切变成 Markdown

Markdown 是唯一来者不拒的格式。网页、AI 对话、PDF、Word 文档，都能转进来。

**你的收集工具箱：**

| 来源 | 怎么变成 Markdown |
|---|---|
| 网页文章 | [URL 导入](https://toolcraftbox.com/tools/markdown)——粘贴链接，得到干净的 Markdown |
| AI 对话 | 让 ChatGPT/Claude"用 Markdown 输出，带标题和列表" |
| PDF / Word | 先转成 Markdown，再粘进编辑器 |
| 一闪而过的想法 | 带 Markdown 编辑器的笔记应用，或直接一个 `.md` 文件 |

[Markdown 工作台](https://toolcraftbox.com/tools/markdown) 一次覆盖前三种：导入 URL、粘贴 AI 回复，几秒就是一篇干净笔记，不用清理格式。

> **收集的黄金法则：** 保存只允许"一步"。如果保存要花超过十秒，你就不会去存。粘贴 + 起个文件名，就是全部流程。

## 第 2 层：整理——每篇笔记同一个骨架

一篇笔记只有形状可预测，才能被找到。每次都套同一个模板，让未来的你清楚地知道去哪找。

```markdown
---
title: <这篇在讲什么>
source: <网址，或书名+页码>
date: 2026-09-02
tags: [主题, 子主题]
---

## TL;DR
最多三行。你会怎么跟别人一句话说清楚？

## 要点
- 要点一
- 要点二

## 引用
> "值得原样保留的那句话，附上出处。"

## 疑问
- 还有什么不清楚？
- 用之前要核实什么？

## 行动
- [ ] 跟进 X
```

五个小节，每次都是。这就是全部整理系统。不用维护文件夹，不用争论分类法——一个固定的骨架就够了。

## 第 3 层：连接——让笔记彼此关联

单篇笔记是事实。**被连接**的笔记才是论证。研究笔记从这一层开始变成思考。

**三种便宜的连接方式：**

1. **双向链接** —— 笔记提到另一篇时写 `[[另一篇笔记]]`。绝大多数 Markdown 应用（Obsidian、Logseq 等）会自动索引成图谱。
2. **每个主题一张索引** —— 一篇"MOC"（内容地图）笔记，列出该主题下的所有笔记。话题重新出现时，它就是入口。
3. **新旧版本对比** —— 一篇笔记演化了几周，丢进[文本 Diff 对比器](https://toolcraftbox.com/tools/text-diff-checker)看你的想法到底怎么变的。绿色是你学到东西的地方。

## 第 4 层：检索——几秒内找到它

三个月后还能找到"那一个东西"，笔记系统才算值回票价。

- **搜索打败文件夹。** 一个装满 `.md` 文件的目录 + 全文搜索（任何好编辑器都有），胜过手工搭的目录树。
- **维护一张运行索引。** 你的 MOC 笔记同时充当每个研究项目的目录。
- **定时回顾。** 每周花 5 分钟扫一遍上周的"疑问"和"行动"栏。这一步把笔记变成知识。
- **要分享就导出。** 用 [Markdown 工作台](https://toolcraftbox.com/tools/markdown)直接从 Markdown 渲染一份体面的 PDF 或 Word——不用重新排版，不用粘进 Word。

## AI 的价值在哪里

上面的系统不需要 AI 也能跑。有了 AI，枯燥的部分直接消失：

- **总结代替抄录** —— 粘贴长文，让它按你的模板格式输出 5 条 TL;DR。
- **生成标签和链接** —— 问"这篇你会给哪 3 个标签，它和我现有哪些笔记相关？"
- **提取引用** —— "把最值得引用的三句话抽出来，附上出处。"
- **拷问来源** —— "把这篇文章变成一组问答，我直接粘进笔记。"

注意：AI 的输出仍然要进同一个模板。把 AI 的总结粘进骨架里，而不是绕开骨架。

## 60 秒搭建

1. 打开 [Markdown 工作台](https://toolcraftbox.com/tools/markdown)
2. 用上面的模板建一篇笔记，存成 `_template.md`
3. 下次读到值得留的东西：URL 导入 → 粘贴 → 调整 → 保存
4. 每周：扫一遍疑问/行动，补链接，结束

这就是整个系统。搭建不到一小时，之后每篇笔记三十秒。

## 常见问题

### 这不就是"用个笔记应用"吗？

应用是最不重要的部分。关键是 Markdown：它是纯文本，你的笔记比任何应用、系统、公司都活得久。在 Obsidian、VS Code、终端之间切换——笔记原封不动跟着走。

### Obsidian 还是 Notion？

两者都能配合 Markdown 工作流。Obsidian 偏向纯文本文件和双向链接；Notion 更一体化，但数据存在自家格式里。如果你在意长期归属，本地 Markdown 文件胜出。

### 笔记里的图片和 PDF 怎么办？

存在 `.md` 文件旁边，用路径引用。Markdown 原生支持图片（`![](image.png)`），链接的 PDF 在任何 Markdown 应用里都能打开。

### 没有文件夹不会乱吗？

文件夹仍然有用——用在**项目**层面（`research/2026/markdown-history/`）。项目内部，让标签和链接来组织。文件夹管项目，链接管想法。

### 引用格式怎么处理？

让模板里的 `source` 字段保持诚实：网址 + 标题 + 访问日期。学术写作再加一个 `citations` 引用区；深入研究可以用 Markdown 友好的文献管理工具。

### AI 能读我的整个笔记库吗？

不能直接读——笔记在本地。但你可以让 AI 处理单篇笔记（总结、打标签、连链接），或把笔记目录导出给工具建索引。对多数研究，逐篇的 AI 辅助已经够用。

## 总结

研究笔记系统是四层结构，不是一个产品：

1. **收集** —— 任何内容十秒变成 Markdown
2. **整理** —— 一个模板，五个小节，每篇都套
3. **连接** —— 双向链接 + 主题索引
4. **检索** —— 搜索、回顾、导出

AI 消掉了摩擦：总结、打标签、连链接从几分钟变成几秒。而且因为一切都是纯文本 Markdown，这套系统免费、可移植、永久。
